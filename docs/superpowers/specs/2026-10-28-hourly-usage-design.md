# 用量页小时统计设计

- 日期：2026-10-28
- 状态：待用户复核
- 范围：用量页新增「日 / 小时」粒度切换，图表与 KPI 支持小时拆分
- 不在范围：接入点明细小时化、时区换算、独立小时页面、轮询频率调整、后端接口协议变更

## 1. 目标

BytePlus Ark 的 `GetInferenceUsage` 支持 `QueryInterval=Hour`，后端 `/api/usage` 也已透传该参数，但前端固定按日查询。目标是在用量页把每天拆成 24 个小时桶展示 token 用量，并让顶部总览图、账户展开图与 KPI 口径一致。

## 2. 现状事实（已核实）

| 项        | 事实                                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 接口      | `/api/usage?interval=Hour` 线上实测返回 `{Day: "2026-10-27", Hour: 9, TotalTokens: ...}`                                                          |
| Hour 取值 | 0–23；Ark 只返回有数据的时段，缺失小时需要前端补 0                                                                                                |
| 文档      | `QueryInterval=Hour` 时 `StartTime/EndTime` 仍为 `yyyy-mm-dd`；返回字段含 `Hour`（文档示例类型为 STRING，实测 BytePlus 返回数字）；**未声明时区** |
| 排序      | `src/ark/usage.ts` 仅按 `Day` 排序，小时行顺序不稳定                                                                                              |
| 前端      | `UsageView` 固定 `interval: 'Day'`；`DailyBars` 按 `Day` 建 Map，小时行会被覆盖为最后一条                                                         |
| KPI 缺陷  | 今日 token 使用 `find(Day === today)`，小时模式下只取当天第一行，需改为按天求和                                                                   |

## 3. 已确认决策

| #   | 决策       | 结论                                                           |
| --- | ---------- | -------------------------------------------------------------- |
| Q1  | 交互形态   | 用量页顶部新增「日 / 小时」分段切换，整页图表跟随              |
| Q2  | 跟随范围   | 顶部总览图与每个账户展开图都跟随粒度                           |
| Q3  | 接入点明细 | 不跟随，继续按日                                               |
| Q4  | 时区       | 原样展示 Ark 返回的 `Hour`，不做换算；界面标注「未做时区换算」 |

## 4. 交互设计

- 页头操作区：`[日] [小时]` 分段控件，与现有范围控件并列
- 范围快捷项：
  - 日模式：今日 / 近 7 天 / 近 30 天 / 自定义
  - 小时模式：今日 / 近 3 天 / 近 7 天 / 自定义
- 跨度上限：
  - 日模式：30 天（含首尾 31 天，Ark 上限）
  - 小时模式：6 天（含首尾 7 天，共 168 个小时槽位）
  - 从日模式切到小时模式时，若当前跨度超过 6 天，自动切为「近 7 天」
- 图表：
  - 单日：24 根柱，横轴标 `00:00 / 06:00 / 12:00 / 18:00 / 23:00`
  - 多日：每天 24 根柱，横轴在每个零点标 `MM-DD`
  - Tooltip：`10-28 13:00 总 1,234 · 输入 800 · 输出 434 · 请求 3`
- 文案：
  - 总览标题：日模式「全部账户 · 逐日总 token」，小时模式「全部账户 · 逐小时总 token」
  - 图表提示：小时模式追加「按 Ark 返回的小时合计，未做时区换算」
  - 账户展开提示：日模式「逐日明细」，小时模式「逐小时明细」
- KPI：今日 = 当天所有小时求和；区间合计 = 区间内全部行求和；请求数同口径

## 5. 数据流

```
UsageView
  ├─ granularity: 'day' | 'hour'
  ├─ fetchUsage({ interval: granularity === 'hour' ? 'Hour' : 'Day' })
  ├─ keys: day → days[]（YYYY-MM-DD）
  │        hour → days × 24（YYYY-MM-DD HH）
  ├─ combinedRows: keys × 各账户行，缺失补 0
  ├─ DailyBars(rows, days, granularity)
  └─ 账户展开：DailyBars(rows, days, granularity)
```

`BreakdownTable` 仍调用 `<DailyBars rows={ep.daily} days={days} />`，不传粒度，行为不变。

## 7. 关键实现约定

- key 格式：日 `YYYY-MM-DD`；小时 `YYYY-MM-DD HH`（两位补零）
- `Hour` 可能是字符串或数字，统一 `Number(row.Hour)` 后补零
- 缺失小时不丢弃，前端按完整 keys 渲染 0 值柱
- `TotalTokens` 等数值字段在后端已按 `BIGINT/INTEGER/DOUBLE` 转成数字
- 小时模式上限仅前端约束；后端仍保留 31 天校验作为兜底

## 9. 风险与对策

- **时区未知**：先原样展示，界面标注未换算；验收时用 API Explorer 对照某时段真实用量。
- **小时无数据**：前端补 0，图表不断档。
- **图表密度**：小时最多 168 点，柱宽下限 3px；不提供 30 天小时视图。
- **性能**：请求次数不变，仅单次返回行数增加；账户展开与明细表请求逻辑不变。
- **回滚**：功能集中在用量页与图表组件；后端排序修正可独立保留。
